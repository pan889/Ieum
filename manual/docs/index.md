# Ieum (이음)

> *이음* — 한국어로 "잇는 것". 흩어진 이슈·문서·요청을 하나로 잇는다는 뜻.

**Jira + Confluence + JSM(서비스데스크)를 대체하는 셀프호스팅 협업 플랫폼입니다.**
데이터는 여러분의 인프라에만 있습니다. 외부 SaaS 없이 완전히 동작합니다.

## 왜 세 개를 하나로

이슈·문서·티켓을 다른 도구로 쓰면 **셋이 서로 끊깁니다.** 티켓에 걸린 문서를
찾으려면 창을 옮겨야 하고, 권한은 세 곳에서 따로 관리되고, 검색은 세 번
합니다.

Ieum 은 셋을 **같은 사용자·권한·검색·알림** 위에 올립니다.

- **티켓은 이슈의 한 종류입니다** — 고객이 포털로 낸 요청이 상담원에게는
  이슈로 보입니다. SLA 와 큐가 그 위에 얹힙니다.
- **문서와 이슈가 서로를 가리킵니다** — 문서에서 `::issues` 로 이슈 목록을
  그리고, 이슈에서 그 문서를 역으로 찾습니다.
- **검색이 한 상자입니다** — 이슈와 문서를 한 번에 찾고, 권한은 질의에
  얹혀서 볼 수 없는 것은 애초에 결과에 안 들어옵니다.

## 무엇이 들어 있나

| | |
|---|---|
| **이슈** | 프로젝트 계층, 커스텀 필드, 워크플로우, 시간 추적, 이슈 관계, 일괄 편집, 반복 이슈 |
| **계획** | 칸반 보드(스윔레인), 스프린트와 번다운, 간트, 캘린더 |
| **위키** | 스페이스, 문서 트리, 판 비교, 인라인 코멘트, 템플릿, 매크로, **동시 편집** |
| **서비스데스크** | 고객 포털, 요청 유형, 큐, SLA와 에스컬레이션, 이메일 채널, KB 추천, CSAT, 승인, 자산(CMDB) |
| **찾기** | 통합 검색(한국어 형태소), 질의 언어 IQL, 저장 필터, 집계 리포트 |
| **관리** | OIDC·SAML SSO, 2FA 강제, SCIM 프로비저닝, 역할·권한, 감사 로그 |
| **잇기** | 웹훅, 개인 액세스 토큰, 앱 슬롯, 코드 저장소 연동 |

## 규모와 성능 목표

| 축 | 목표 |
|---|---|
| 데이터 | 이슈 50만 / 문서 10만 / 첨부 500GB |
| 응답 | 목록 p95 400ms, 검색 p95 800ms |
| 동시 접속 | 300명이 4 vCPU / 16GB 단일 노드에서 |

이 숫자는 **목표**입니다. 어디까지 실제로 확인했는지는
[릴리스 노트](https://github.com/pan889/Ieum/blob/main/CHANGELOG.md)에 있습니다 —
확인한 것과 못 한 것을 나눠 적었습니다.

## 한국어

한국어가 1급입니다. 화면 기본이 한국어이고(영어도 완전 지원), 검색은
PGroonga 로 형태소를 봅니다 — `배포` 로 찾으면 `배포를` 이 적힌 문서가
나옵니다. 알림 문구도 번역이 아니라 한국어로 씁니다.
