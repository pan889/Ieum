# 이슈와 프로젝트

## 프로젝트

프로젝트는 이슈가 담기는 곳이고, **권한이 붙는 자리**입니다. 계층을 가질 수
있어서 `플랫폼 → 플랫폼/검색` 처럼 나눌 수 있고, 상위에서 준 역할은 하위로
내려갑니다.

**키는 바꿀 수 없습니다.** `ENG` 로 만들면 이슈가 `ENG-1`, `ENG-2` 가 되고,
그 문자열이 링크·커밋 메시지·메일·웹훅에 남습니다. 나중에 바꾸면 그 전부가
가리키는 곳을 잃습니다.

리드와 공개 여부를 정할 수 있습니다. 공개 프로젝트는 로그인한 사람 누구나
읽고, 비공개는 역할을 받은 사람만 봅니다.

## 이슈

### 만들기

`이슈 → 새 이슈`. 프로젝트와 요약만 필수입니다. 종류(작업·버그·에픽·하위
작업)는 워크플로우와 짝입니다.

### 상태와 전이

상태는 **워크플로우가 정한 곳으로만** 옮겨집니다. 열려 있는 버튼이 곧 갈 수
있는 곳이고, 갈 수 없는 곳은 버튼이 없습니다 — 눌러 보고 거절당하는 것보다
낫기 때문입니다.

전이가 막히는 경우가 둘 있습니다.

- **필수 필드**가 비어 있다 — 무엇이 비었는지 말해 줍니다.
- **승인을 기다린다** — 승인 관문이 걸린 요청 유형입니다. 승인·거절·취소
  전에는 착수도 종료도 못 합니다.

### 관계와 계층

- **하위 작업**은 부모의 진행률에 반영됩니다. 부모는 자식이 다 닫히면
  진행률 100% 가 되지만, **자동으로 닫히지는 않습니다** — 닫는 것은 사람의
  판단입니다.
- **관계**(막는다 / 막힌다 / 관련 / 중복)는 양방향으로 보입니다. 한쪽에서
  걸면 반대쪽에도 나타납니다.
- **에픽**은 묶는 상자입니다. 보드에서 스윔레인으로 쓸 수 있습니다.

### 시간

추정과 실적을 따로 적습니다. `2h 30m`, `1d` 처럼 적으면 됩니다. 실적은
기록마다 날짜와 메모가 남아서 나중에 리포트로 셀 수 있습니다.

### 첨부

끌어다 놓거나 고릅니다. 파일은 오브젝트 스토리지로 **브라우저에서 직접**
올라가고(서버를 거치지 않습니다), 서버는 서명된 주소만 발급합니다. 그래서
큰 파일이 API 를 붙잡지 않습니다.

### 댓글과 멘션

`@` 로 사람을 부르면 그 사람에게 알림이 갑니다. 알림은 인앱과 메일 둘 다
가고, 받는 방식은 각자 `알림 → 환경설정` 에서 고릅니다.

## 목록에서 여러 개를 한 번에

이슈 목록에서 고른 뒤 `일괄 편집` 을 누르면 담당자·상태·우선순위·라벨을
한 번에 바꿉니다. **바꾸지 않을 칸은 비워 둡니다** — 비운 칸은 "그대로
둔다" 는 뜻이고, "비우라" 는 뜻이 아닙니다.

`CSV 내보내기` 는 지금 목록에 보이는 것을 그대로 내립니다 — 질의를 바꾸면
내려가는 것도 바뀝니다.

## 커스텀 필드

`설정 → 커스텀 필드` 에서 정의합니다. 종류에 따라 화면의 칸 모양이 달라집니다
(글·숫자·날짜·고르기·여러 개 고르기·사람·확인란·URL).

정의한 필드는 IQL 에서 `cf["field_key"]` 로 씁니다. 별칭을 붙이면 그 이름으로도
됩니다.

## 반복 이슈

정기 점검처럼 주기로 생기는 일은 `반복` 에서 규칙을 만듭니다. 워커가 때가 된
규칙을 찾아 이슈를 만들고, **만들 때의 템플릿을 그 규칙이 들고 있습니다** —
과거에 만든 이슈를 고쳐도 다음 것에 영향을 주지 않습니다.

## 코드 저장소와 잇기

`설정 → 저장소` 에 저장소를 등록하고 웹훅을 걸면, 커밋 메시지에 이슈 키
(`ENG-12`)가 있는 커밋과 PR 이 그 이슈에 붙습니다.

**우리가 호스트 API 를 부르지 않습니다** —
받기만 합니다. 그래서 토큰을 우리가 들고 있지 않고, 대신 웹훅이 꺼져 있던
사이의 커밋은 안 붙습니다.

`fixes ENG-12` 는 **기록만** 하고 상태를 옮기지 않습니다. 커밋은 되돌려지기
때문입니다.
